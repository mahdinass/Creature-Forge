## Recovery procedure (Git Bash, from the repository root)
```bash
D=$(mktemp -d)
# 1) fetch: off-machine copy (or copy the files from the local archive folder instead)
gh release download archive-ce-artifacts-2026-10-18 --repo mahdinass/Creature-Forge --dir "$D"
#    local alternative: cp ~/CreatureForge-archive/2026-10-18/* "$D"/
# 2) verify the archive, then every file
( cd "$D" && sha256sum -c creature-forge-ce-artifacts-2026-10-18.tar.gz.sha256 )
tar -xzf "$D/creature-forge-ce-artifacts-2026-10-18.tar.gz" -C "$D"
( cd "$D/creature-forge-ce-artifacts-2026-10-18" && sha256sum -c --quiet SHA256SUMS && echo ALL OK )
# 3) the archive's list must equal the one committed in Git
cmp "$D/creature-forge-ce-artifacts-2026-10-18/SHA256SUMS" docs/archive/ce_artifacts_2026-10-18.SHA256SUMS
# 4) restore without overwriting newer files (ledgers keep growing), then check in place
cp -rn "$D/creature-forge-ce-artifacts-2026-10-18/artifacts" "$D/creature-forge-ce-artifacts-2026-10-18/infra" .
sha256sum -c --quiet docs/archive/ce_artifacts_2026-10-18.SHA256SUMS && echo RESTORED OK
```
- **`tar` and Windows paths:** in Git Bash, `tar` reads a `C:\...` path as a remote host. Use `/c/...` or `mktemp -d`
  paths, or add `--force-local`.
- **For a held-out-style run on the VM:**
  - the memory inputs go to `~/dev/<slot>/artifacts/mem/` with the same file names (`probe_dev.jsonl`,
    `pilot*_shard*.jsonl`);
  - check them against `protocol.json` `inputs` before launching;
  - copying needs a started VM, which is paid, so do it only for an approved run.
- **Do not restore** the spend ledgers over newer ones. `cp -n` keeps existing files; a mismatch reported in step 4 for a
  ledger file is expected if it has grown since 2026-10-18.
