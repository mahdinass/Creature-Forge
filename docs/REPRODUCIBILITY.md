# Cross-platform reproducibility of pre-registered evidence

## Finding (2026-10-13)
The Phase 1 pre-registration (`experiments/phase1/protocol.json`) hashes prompts whose embedded evidence was regenerated by MuJoCo on Windows. CI (Linux) rebuilt different prompt hashes for **both** prompts (legacy `4f92a013...`, forensic `48a8962d...`). An earlier note saying the legacy hash matched on Linux was wrong: the legacy assertion simply never ran because the forensic one failed first. A byte-hash cannot distinguish a changed experiment from changed low-order float bits.

## Diagnosis (measured)
| | Windows (registered) | Linux A (= CI) | Linux B |
|---|---|---|---|
| Python | 3.11.9 | 3.12.14 | 3.12.14 |
| MuJoCo | 3.15.0 | 3.15.0 | 3.15.0 |
| NumPy | 2.4.6 | 2.5.4 | 2.4.6 |
| Result vs registered | exact, 0 float diffs | 10 float diffs | identical to Linux A |

* Linux with NumPy 2.4.6 and 2.5.4 produced **identical** evidence, so the difference is the platform (libm/SIMD/compiler), not NumPy or the Python version.
* Of 50 (legacy) / 262 (forensic) evidence leaves there are **0 structural or categorical differences**: schema, seeds, fall/no-fall, fall_rate, event table, contact-transition sequence, per-seed forensics and all integers/strings/booleans are identical. Ten unrounded floats differ, max relative **3.9e-14** (absolute 1.3e-15 on torso height), median 1.1e-15. All forensics fields are published rounded (3-4 decimals) and matched exactly.
* Sensitivity probe (Windows): perturbing `torso_mass` by relative 1e-12 / 1e-10 / 1e-8 / 1e-6 changes the outputs by 3.3e-11 / 3.3e-9 / 3.3e-7 / 3.3e-5, a linear, non-chaotic response (gain ~33). Platform noise corresponds to a ~1e-15 relative input perturbation, i.e. machine epsilon.

## Two independent checks (`creature_forge/reproducibility.py`, tests in `tests/test_phase1.py`)
**A. Historical integrity (exact, every platform).** The stored `prompts.*.messages` must hash, under the canonical serialization `json.dumps(messages, sort_keys=True, separators=(",", ":")).encode()` then SHA-256, to the registered hashes (also pinned in the test so editing `protocol.json` alone cannot pass). Nothing is regenerated.

**B. Physics reproducibility (tolerance-based).** Evidence regenerated by MuJoCo is compared field by field with the evidence embedded in the frozen prompt:
* **Exact:** key sets, list lengths, strings, booleans, `None`, integers and value *types* (int-vs-float drift fails). Failure classification, event names/order, contact transitions and seeds cannot change silently. A separate test asserts the scientific conclusions (fall rate, fell, transitions, events, per-seed forensics) exactly.
* **Tolerance (floats only):** `|a-b| <= 1e-12 + 1e-9*max(|a|,|b|)`. Justification: observed deviation 3.9e-14 leaves 4 orders of headroom; 1e-9 relative equals a ~3e-11 relative parameter change (gain 33), about 5 orders below a physically meaningful design change (1e-6); it is far below the 1 ms integration step, so a discrete event moving by one step is caught. A rounded published value flipping by one unit is **not** tolerated (reported as a possible rounding-boundary flip).
* Differences are always printed (path, reference, new, abs, rel, OK/BAD) in the test output and CI log.

## Dependencies
`pyproject.toml` pins `mujoco==3.15.0` and `numpy>=2.4.6,<2.6` (the two verified releases). Python 3.11 (Windows) and 3.12 (CI) are verified. CI prints interpreter, platform, NumPy and MuJoCo versions.

## Rules for future experiments (historical Phase 1 records are NOT converted)
A new registration records: (1) the immutable exact prompt sent to the model, (2) its SHA-256 and serialization, (3) `environment_fingerprint()` (Python, MuJoCo, NumPy, platform, machine), (4) independently reproduced reference evidence with the tolerance policy (`registration_provenance()`). A live replay must send the frozen prompt byte-for-byte or be registered as a new experiment. `scripts/run_phase1_live.py` still refuses to run when the prompts rebuilt locally do not hash to the registered values, so on a platform with different low-order bits (for example Linux) it refuses; this authorization safeguard is intentionally unchanged.
